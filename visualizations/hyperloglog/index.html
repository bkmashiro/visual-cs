How HyperLogLog Works

HyperLogLog estimates how many distinct items are in a data stream using very little memory — O(m) registers instead of storing all items.

Hash: Each item is hashed to a uniform bit string (32 bits here).

Register index: The first b bits select one of m = 2^b registers.

Leading zeros: Count trailing leading zeros in the remaining bits (from the left). This is the position of first 1-bit, giving an exponential observable.

Update: Each register stores the maximum leading-zero count seen for its bucket.

Estimate: The harmonic mean of 2−M[j] across all registers gives the cardinality estimate.

Harmonic Mean Formula

E = αm · m² · (Σ 2−M[j])−1

Where α_m is a bias-correction constant, m is the number of registers, and each M[j] is the max leading zeros + 1 seen in register j.

The harmonic mean dampens the effect of outliers (unusually long runs of zeros), making it more robust than the arithmetic mean.

Bit Layout

■ First b bits — register index

■ Leading zeros in remaining bits

■ Remaining payload bits

The key insight: a long run of leading zeros in a random hash is exponentially unlikely, so seeing one implies we've processed many distinct items.

• Analytics — unique visitors, DAU/MAU metrics

• Networking — distinct IPs in traffic streams
